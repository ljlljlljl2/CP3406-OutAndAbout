# Gibbs reflection guide - not a completed submission

Write 500–1000 words over 1–2 pages using your own actual experience. Do not claim work or tests you have not performed. Suggested allocation below totals about 750 words. Replace prompts with your own account, then export to PDF.

## 1. Description (100 words)
What daily need does your app address? Which starter components did you keep? What did you implement yourself, and what assistance did you receive?

## 2. Feelings (80 words)
How did you feel opening Android Studio, understanding the starter, and running the app? Describe a specific genuine moment.

## 3. Evaluation (130 words)
Which features actually worked in testing? Which failed or were difficult? Include one concrete result from TESTING.md, plus limitations and the contribution of AI assistance.

## 4. Analysis (220 words)
Explain why ViewModel and StateFlow separate logic from composables. How does the repository allow fake data in tests? Why cancel an obsolete city request? What caused a real error you encountered, and how did you diagnose it? Explain one code section in your own words.

## 5. Conclusion (100 words)
What can you now explain or perform independently? Which concepts still need practice? Evaluate whether the app provides useful information at a glance.

## 6. Action plan (120 words)
Give specific next steps: e.g., start earlier with genuine regular commits, test offline states sooner, add persistent preferences or city search, improve accessibility, and verify AI-generated code against documentation.

Before writing the final reflection, record: your device/emulator, whether the app ran, one actual error and fix, one test result, the parts you personally changed, and what you learned. These facts are needed for an honest final reflection.
